# Synthetic Ingestion API evidence example

## Purpose

This directory shows the public structure produced by the `minimal_publication` profile for an Ingestion API v2 exchange. The directory name `t4-ingestion-api` is historical: the profile belongs to the asset, not to slot T4.

The JSON files were generated by the evidence exporter from a synthetic fixture containing fake canary values. They were not derived from the validated PRE run and do not prove that a specific execution occurred.

## Inventory

- `sanitized_summary.json`: allowlisted flow, topology, placeholder identifiers, and phase statuses.
- `sanitized_manifest.json`: allowlisted download metadata with the payload excluded and the source payload hash withheld.
- `validation_status.json`: synthetic semantic-validation status and publication checks.
- `package_manifest.json`: generated inventory rows for the complete synthetic archive.

The package inventory contains SHA-256 values calculated over synthetic metadata files. These are not hashes of a private business payload.

This versioned example remains JSON-only. `tools/export_evidence_to_excel.py` can project the same canonical sanitized model into a workbook. A generated workbook is not committed here.

## Exclusions

This example contains no:

- downloaded payload or preview;
- raw phase request or response;
- phase environment file;
- data-address content;
- API key, password, JWT, or authorization value;
- endpoint host or local filesystem path;
- real run suffix, UUID, or execution identifier;
- hash from a private business payload.

## Interpretation

All execution identifiers are placeholders. The technical connector fields describe topology only:

- `CONN-CITYCOUNCIL` is the technical provider connector;
- `CONN-COMPANY` is the technical consumer connector.

Ingestion API v2 does not replace the CSV/B2/InesDataStore legacy baseline. This synthetic example is not delivered assessment evidence.

A `minimal_publication` bundle is eligible for publication after manual review when `publication_ready=true`. The matching workbook additionally requires the complete OOXML audit and manual workbook review. Packages that include `standard_internal` slots remain internal.

See [Evidence Publication Policy](../../../docs/evidence-publication.md) and the [evidence export CLI](../../../tools/tools_README.md) before using any generated package in a demonstration or public release.
